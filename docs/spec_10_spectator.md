# 10. 观战（规格稿 v1）

> 归属：AI 设计位。约束（GDD 第 10 节）：
> spectator 为**纯订阅客户端**，不进游戏逻辑 tick，不参与模拟；
> 这是 WebGL 观战端可运行的前提。

## 10.1 数据订阅（仅三样）

| 流 | 频率 | 内容 | 可隐藏项 |
|----|------|------|----------|
| `players` | 10Hz | 位置（半精度）、朝向、血量分段（呼吸级）、倒地/撤离状态 | 无 |
| `monsters` | 5Hz（可选） | 位置（模糊化 ±3m 可配）、怒气段、激活状态 | **类型名/ID 默认隐藏** |
| `events` | 事件驱动 | 击杀、救援、任务完成、怒气跃迁、撤离、倒地 | 无 |

规则：
- 三流均为**服务端广播**，观战端只读；禁止向服务端发送任何状态。
- 观战端不接收：任务物品细节、玩家背包、音频 RPC、伤害数值明细。

## 10.2 广播格式

```json
{ "t": 12345, "type": "players", "items": [[pid,x,z,yaw,hp_band,flags], ...] }
{ "t": 12345, "type": "monsters", "items": [[mx,mz,anger_band,alive], ...] }
{ "t": 12345, "type": "event", "kind": "rescue", "a": "P-003", "b": "P-007" }
```

- 位置使用半精度量化（`int16 * scale`），网格化 0.05m。
- `monsters` 流受 `spectate.hide_monsters` 配置控制（解说/悬念模式）。
- WebGL 端走 WebSocket + JSON 或二进制 delta（二选一由客户端能力协商）。

## 10.3 镜头模式

| 模式 | 说明 | 输入 |
|------|------|------|
| 自由 `free` | 无碰撞飞行；可穿墙，边缘泛光提示 | WASD + 鼠标 |
| 跟随 `follow` | 锁定某玩家背后 3m，延迟 0.15s | 数字键切换目标 |
| 导演 `director` | 自动在事件点间切换（击杀/救援/撤离） | 自动 + 人工覆盖 |

约束：镜头不触发任何游戏内感知（观战坐标对 AI 不可见）。

## 10.4 延迟与带宽预算

| 项 | 目标 |
|----|------|
| 观战端到服务端延迟 | < 5s（允许，用于防窥屏） |
| 带宽/观战端 | ≤ 40KB/s（16 人局） |
| 广播 tick | 独立于游戏 tick（10Hz/5Hz），不占游戏 tick 预算 |
| 服务端开销 | 每观战端 < 0.1ms/tick；上限 20 观战端/房 |

## 10.5 权限与防滥用

- 观战开关：房主可设 `spectate.policy = off / friends / public`。
- 延迟广播：默认 `delay_s = 5`（防实时窥屏作弊）。
- 断线后 180s 自动转观战（与 9.4 衔接）。
- 观战端不得获取 `resume_token`，不可转回玩家身份（除房主批准）。

## 10.6 验收口径

- 画面/日志：ImGui/日志显示 `spectate_clients=N, out_kbps=.., delay_s=..`。
- 服务端证明：观战连接无写权限（任何上行 >0 字节即告警并断开）。
- 帧耗时：广播组装 < 0.1ms/room/次。
- WebGL：观战页面在无插件浏览器可连续运行 30min，内存增长 < 50MB。
